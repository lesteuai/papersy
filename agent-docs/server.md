# Server Modules

Server-only modules: database access, authentication, retrieval, ingestion, and the LLM agent. Located in `src/lib/server/`.

**Never import in browser code** (`.svelte` files, `+page.ts`, `+layout.ts`). Safe to import in `+server.ts` and `hooks.server.ts`. Note there is no `+page.server.ts` anywhere in the app; every page is client-fetched.

```
src/lib/server/
├── auth.ts           <- better-auth instance
├── llm.ts            <- OpenAI-compatible clients against OpenRouter (chat, embeddings, health checks)
├── agent.ts           <- createProjectAgent: LangChain agent with a retrieve tool
├── retrieval.ts        <- hybridSearch: vector arm + full-text arm, fused with RRF
├── rrf.ts               <- fuseRrf: pure Reciprocal Rank Fusion, no database access
├── extract.ts           <- extractDocument: markitdown-ts dispatch per file extension
├── limits.ts             <- MAX_CHARS and checkCharLimit
├── ingest.ts             <- ingestDocument: background chunk/embed/index pipeline
├── ingest-jobs.ts        <- activeIngestions: shared AbortController map for ingestion cancellation
└── db/
    ├── index.ts      <- Drizzle ORM client
    ├── schema.ts     <- project, chatSession, chatMessage, document, documentChunk + re-exports auth.schema
    └── auth.schema.ts <- generated by `npm run auth:schema` (user, session, account, verification)
```

## auth.ts

Exports `auth` — the better-auth instance, and `requireSession` — a shared auth guard.

### Config

- **Database**: Drizzle adapter with PostgreSQL
- **Origin**: `ORIGIN_DEV` in development (`NODE_ENV !== 'production'`), `ORIGIN` in production
- **Provider**: email/password, no sign-up cap
- **Email verification**: `requireEmailVerification: false`. No verification email is sent; a newly signed-up user can log in immediately. The `verify-email` and `reset-password` routes are left in place but unreachable through normal sign-in.
- **Forgot password**: built-in password reset flow with `sendResetPassword` callback (logs the reset URL to console; TODO real email sending)
- **Plugins**: `sveltekitCookies(getRequestEvent)` — handles cookie injection per request

The former `MAX_USERS` constant and the `beforeSignUp` hook that enforced a 100-user cap are gone. No `USER_LIMIT_REACHED` error path remains anywhere in the code.

### Usage

```ts
import { requireSession } from '$lib/server/auth';

const session = await requireSession(request.headers);
// session.user.id, session.user.email
// throws 401 automatically if no session
```

## db/index.ts

Exports `db` — Drizzle ORM client connected to PostgreSQL via the `postgres-js` driver. The connection string is built from `PG_HOST`, `PG_PORT`, `PG_USER`, `PG_PASSWORD`, `PG_DATABASE` and has `?sslmode=require` appended explicitly, because the managed Postgres host refuses insecure connections. Without it the failure mode is a silent hang, most visibly during `drizzle-kit migrate`. `drizzle.config.ts` builds the same string the same way for CLI migrations.

```ts
import { db } from '$lib/server/db';
import { project, chatSession } from '$lib/server/db/schema';
import { eq } from 'drizzle-orm';

const rows = await db.query.project.findMany({
  where: eq(project.userId, userId),
  with: { chatSessions: true }
});
```

## db/schema.ts

Custom Drizzle schema. Re-exports `auth.schema.ts`.

### Custom Tables

**`project` table:**
- `id` (PK text)
- `userId` (FK→user, cascade delete)
- `name` (text, not null)
- `createdAt` (defaultNow)

**`chatSession` table:**
- `id` (PK text)
- `projectId` (FK→project, cascade delete)
- `userId` (FK→user, cascade delete)
- `name` (nullable text) — `NULL` means not named by the user; the display label is derived from the first user message at read time. Only an explicit rename ever writes this column, so a user-set name can never be silently overwritten.
- `createdAt` (defaultNow)

**`chatMessage` table:**
- `id` (PK text)
- `sessionId` (FK→chatSession, cascade delete)
- `role` (text, not null: `'user'` | `'assistant'`)
- `content` (text, not null)
- `createdAt` (defaultNow)

**`document` table:**
- `id` (PK text)
- `projectId` (FK→project, cascade delete)
- `userId` (FK→user, cascade delete)
- `name` (text, not null)
- `kind` (text, not null: `'pdf'` | `'markdown'` | `'text'`)
- `charCount` (nullable integer)
- `status` (text, not null, default `'pending'`; reuses `JobStatus`: pending/processing/storing/done/failed/cancelled)
- `error` (nullable text)
- `createdAt` (defaultNow)

**`documentChunk` table:**
- `id` (PK text)
- `documentId` (FK→document, cascade delete)
- `projectId`, `userId` (denormalized, not null — lets retrieval filter without a join)
- `content` (text, not null)
- `chunkIndex` (integer, not null)
- `embedding` (`vector(1536)`, HNSW index using `vector_cosine_ops`)
- `tsv` (`tsvector`, `GENERATED ALWAYS AS (to_tsvector('english', content)) STORED`, GIN index)

**Relations:** `projectRelations` (→ user, many chatSessions, many documents), `chatSessionRelations` (→ project, → user, many messages), `chatMessageRelations` (→ chatSession), `documentRelations` (→ project, → user, many chunks), `documentChunkRelations` (→ document).

The `paper`, `reference` and `job` tables, and the old pgvector-managed `documents` table, are all gone.

### Auto-Generated Auth Schema

`db/auth.schema.ts` — Auto-generated by running `npm run auth:schema`. Run this after changing `auth.ts` to regenerate. Tables: `user`, `session`, `account`, `verification`.

## llm.ts

OpenAI-compatible clients pointed at OpenRouter. No LangChain vector store or summary schema here anymore.

**`getLlm()`** — `ChatOpenAI` with `model: env.REASONING_MODEL`, `configuration.baseURL: 'https://openrouter.ai/api/v1'`, `configuration.apiKey: env.OPENROUTER_API_KEY`.

**`getEmbeddings()`** — `OpenAIEmbeddings` with `model: env.EMBEDDING_MODEL`, same OpenRouter base URL and key.

**`checkLlmHealth()`** / **`checkEmbeddingHealth()`** — Both ping `https://openrouter.ai/api/v1/models` with a 5-second timeout and the same bearer token. Returns `true` if reachable. Call before invoking the LLM or before vectorization/retrieval to fail fast with a 503.

Verified working values: `REASONING_MODEL=google/gemma-4-31b-it`, `EMBEDDING_MODEL=openai/text-embedding-3-small` (1536 dimensions, matching `documentChunk.embedding`). See `agent-docs/config.md` for how to check remaining OpenRouter budget for the key behind `OPENROUTER_API_KEY`.

## agent.ts

**`createProjectAgent({ projectId, userId, projectName })`** — Builds a LangChain `createAgent`:
1. Defines a `retrieve` tool (`responseFormat: 'content_and_artifact'`) that calls `hybridSearch(projectId, userId, query)` and serializes each chunk as `Source: <document name>\n---\n<content>\n---`
2. Loads `default-prompts/chatbot.txt` once at module load and interpolates `{projectName}`
3. Returns the agent built from `getLlm()`, the `retrieve` tool, and the interpolated system prompt

The caller (`/api/chat`) invokes the agent with the full prior message history plus the new user message, and reads the final assistant message off `result.messages.at(-1)`.

## retrieval.ts

**`hybridSearch(projectId, userId, query)`** → `RetrievedChunk[]` (`{ id, content, source }`):
1. Embeds `query` via `getEmbeddings().embedQuery()`
2. Runs `searchVector` (cosine distance, `ORDER BY embedding <=> ...`) and `searchFullText` (`plainto_tsquery('english', ...)` against `tsv`, ranked by `ts_rank_cd`) in parallel, each scoped to `project_id = $1 AND user_id = $2`, each returning up to `CANDIDATE_DEPTH = 20` chunk ids
3. Fuses both id lists with `fuseRrf` down to 5 ids
4. Hydrates those ids with their content and source document name in one query

Returns `[]` when both arms are empty, which is the path the agent uses to say it does not know and suggest a Google query.

## rrf.ts

**`fuseRrf(lists, opts?)`** — Pure function, no database access, so it is directly unit-testable. Scores each id as `Σ 1 / (k + rank)` across every list it appears in (one-based ranks), sorts descending, returns the top `limit` ids. Defaults: `RRF_K = 60`, `RRF_DEFAULT_LIMIT = 5`. An id present in only one list still scores; empty input yields an empty result.

## extract.ts

**`extractDocument(buffer, filename)`** → `{ kind: 'pdf' | 'markdown' | 'text', text: string }`. Dispatches on the file extension (`.pdf`, `.md`, `.markdown`, `.txt`) and calls `MarkItDown.convertBuffer(buffer, { file_extension })` for all three kinds through the single `markitdown-ts` API. Throws `UnsupportedTypeError` for any other extension and `EmptyExtractionError` when the result has no extractable text (covers scanned-image PDFs and corrupt files alike).

`markitdown-ts` delegates PDF handling to `pdf-parse` internally and returns its output verbatim, so PDF extraction quality is unchanged from before this pivot. `pdf-parse` is no longer a direct dependency in `package.json` and is not imported anywhere in `src/`; it remains only as a transitive dependency of `markitdown-ts`.

## limits.ts

**`MAX_CHARS = 45_000`** and **`checkCharLimit(count)`** — pure check returning `{ ok: true }` or `{ ok: false, message }` naming the actual character count and the limit. This is the only document size limit; there is no page-count limit.

## ingest.ts

**`ingestDocument(documentId, projectId, userId, text, signal)`** — Assumes the document row already exists and the 45,000-char check already passed (both happen in the upload route before this runs). Steps, each checking `signal.aborted` first:
1. Set status `processing`
2. Split `text` with `RecursiveCharacterTextSplitter` (chunk size 1000, overlap 200)
3. Set status `storing`
4. Check embedding health; throw if unreachable
5. Embed all chunks (`getEmbeddings().embedDocuments()`)
6. Insert all `documentChunk` rows in one batch
7. Set status `done`

On any thrown error: `AbortedError` sets status `cancelled`; anything else sets status `failed` with the error's message stored on `document.error`. The `activeIngestions` entry for the document is always removed in a `finally` block.

## ingest-jobs.ts

Exports `activeIngestions` — a module-level `Map<documentId, AbortController>`. Imported by the document upload route (to register a controller), and by the project-delete and document-delete routes (to abort and remove it).

```ts
import { activeIngestions } from '$lib/server/ingest-jobs';

// In the upload handler: register controller
const controller = new AbortController();
activeIngestions.set(documentId, controller);

// In a delete handler: abort in-flight ingestion
activeIngestions.get(documentId)?.abort();
activeIngestions.delete(documentId);
```
