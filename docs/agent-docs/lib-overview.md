# src/lib Overview

Shared, reusable library code exported globally via the `$lib` import alias. Organized by domain: components, icons, styles, stores, types, data, and server utilities.

## Directory Structure

| Directory | Purpose |
|---|---|
| `components/` | Component system (Atomic Design: atoms → molecules → organisms → dedicated) |
| `icons/` | Inline SVG icon library (~20 icons, mostly line style) |
| `scss/` | Global SCSS: reset, variables, theming, breakpoints, typography, markdown, code highlighting, animations |
| `stores/` | Svelte stores (`loggedIn` for auth, `theme` with persistence) |
| `utils/` | Shared TypeScript types and utility constants (`types.ts`, `session-label.ts`, `regex.ts`) |
| `data/` | Static site data (currently: `meta.ts` for SEO defaults) |
| `server/` | Server-only: database (Drizzle), auth (better-auth), retrieval, ingestion, the LLM agent (OpenRouter via LangChain) |
| `index.ts` | Re-exports all public library symbols for convenience |
| `auth-client.ts` | Shared better-auth client for frontend API calls |

## Key Architectural Patterns

### Component Composition

- **Atomic Design** — atoms → molecules → organisms → dedicated
- **No upward dependencies** — lower layers never import higher layers
- **Polymorphic components** — Button and Card render as `<a>` or `<button>`/`<article>` based on props

### Styling

- **CSS-driven theming** — `data-theme` attribute on `<html>`, no JS class manipulation
- **Semantic color tokens** — `--color--{name}` generated by SCSS mixin
- **Responsive mixins** — `@include for-phone-only`, `@include for-tablet-portrait-up`, etc.
- **Scoped SCSS** — no Tailwind in components

### State Management

- **Minimal stores** — `theme` (persistence + DOM), `loggedIn` (auth sync)
- **Local state preferred** — Svelte runes for component-local state
- **Client-side data flow** — every page fetches its own data client-side; there is no `+page.server.ts` anywhere in the app, only a root `+layout.server.ts` returning `{ loggedIn }`
- **`loggedIn` is a cache** — set on successful login/signup and read by pages and `Header` to decide what to render

### Authentication

- **better-auth** — email/password auth with PostgreSQL session storage, email verification off, no sign-up cap
- **Shared client** — `auth-client.ts` exports `getAuthClient()` function (lazy browser-only initialization using `browser` from `$app/environment`, follows SvelteKit best practices)
- **Server validation** — every API route checks `auth.api.getSession({ headers })` via `requireSession`, then verifies row ownership before acting

### Database

- **Drizzle ORM** — lightweight, type-safe ORM, and the sole owner of every table including the vector/tsvector chunk table (no separate vector-store-managed table)
- **PostgreSQL** — pgvector-enabled for vector similarity search, plus native full-text search (`tsvector`/`tsquery`) for the other arm of hybrid search
- **Tables** — auth (user, session, account, verification), workspace (project, chatSession, chatMessage), knowledge base (document, documentChunk)
- **Schema files** — `schema.ts` (custom app tables), `auth.schema.ts` (generated by `npm run auth:schema`)
- **Connection** — built from `PG_HOST`/`PG_PORT`/`PG_USER`/`PG_PASSWORD`/`PG_DATABASE`/`PG_SSL`; the managed host refuses insecure connections

### LLM & Retrieval

- **OpenRouter** — both chat (`REASONING_MODEL`) and embeddings (`EMBEDDING_MODEL`) go through `https://openrouter.ai/api/v1`, authenticated with `OPENROUTER_API_KEY`
- **LangChain** — `ChatOpenAI`, `OpenAIEmbeddings`, `createAgent`, `tool`, `RecursiveCharacterTextSplitter`
- **Hybrid retrieval** — pgvector cosine arm + Postgres full-text arm, fused with Reciprocal Rank Fusion (`fuseRrf`, `k = 60`) down to 5 chunks, scoped to project and user
- **Agent** — a single `retrieve` tool scoped to a project; the system prompt enforces citation, reasoning across chunks, and an "I don't know, try this Google query" fallback when retrieval is empty

### Document Ingestion

- **Extraction** — `markitdown-ts`'s `MarkItDown.convertBuffer` handles `.pdf`, `.md`, `.markdown` and `.txt` through one API; PDF quality is unchanged since it delegates to `pdf-parse` internally
- **Limits** — no page-count limit; the `MAX_CHARS` env var (default 500,000) sets the only size cap
- **Background + cancellable** — `activeIngestions` (a module-level `Map<documentId, AbortController>`) lets a delete request cancel an in-flight ingestion

### Types

- **Centralized in `utils/types.ts`** — utility types, blog/feature types, and app-specific types (`JobStatus`, `Project`, `Session`, `Document`, `ChatMessage`)
- **`session-label.ts`** — `sessionLabel()` (derives a session's display label) and `validateName()` (shared 1-100-char trim-and-validate rule for project and session names)
- **Re-exports in `index.ts`** — available via `$lib`

## Common Import Patterns

```ts
// Components
import Button from '$lib/components/atoms/Button.svelte'
import LoginCard from '$lib/components/dedicated/app/LoginCard.svelte'

// Icons
import ChatIcon from '$lib/icons/chat.svelte'

// Stores
import { loggedIn } from '$lib/stores/auth'
import { theme } from '$lib/stores/theme'

// App types
import type { Project, Session, Document, ChatMessage } from '$lib/utils/types'
import { JobStatus } from '$lib/utils/types'
import { sessionLabel, validateName } from '$lib/utils/session-label'

// Auth client (browser-side)
import { getAuthClient } from '$lib/auth-client'

// Server utilities (server-only: +server.ts, hooks.server.ts)
import { db } from '$lib/server/db'
import { project, chatSession, document, documentChunk } from '$lib/server/db/schema'
import { getLlm, getEmbeddings, checkLlmHealth, checkEmbeddingHealth } from '$lib/server/llm'
import { createProjectAgent } from '$lib/server/agent'
import { hybridSearch } from '$lib/server/retrieval'
import { auth } from '$lib/server/auth'
```
