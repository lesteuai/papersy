# Plan: Fix npm run lint errors and warnings

Status: draft
Request: run 'npm run lint' and work on fixing the errors and warnings

## Approach

`npm run lint` runs `prettier --check . && eslint .`. Both halves fail, for unrelated reasons, so the fix splits in two.

The Prettier half reports 85 files. The root cause is that no `.prettierrc` exists in the repo, even though `prettier-plugin-svelte` and `prettier-plugin-tailwindcss` are installed as devDependencies. Two consequences: Prettier measures every file against its stock defaults (spaces, double quotes, 80 columns) while the codebase is written in the SvelteKit house style (tabs, single quotes), and `.svelte` files are not checked at all because no plugin is registered. Git history contains no deleted `.prettierrc`, so this was never committed rather than lost. I verified by config search that tabs + single quotes + `trailingComma: none` + `printWidth: 100`, the stock `create-svelte` template config, is the best fit at 68 differing files; `printWidth` 80 gives 98 and 120 gives 93, and dropping `trailingComma: none` raises 68 to 94. So the fix is to add that config plus a `.prettierignore`, then run `prettier --write .` to normalize the 68 files that are genuinely unformatted.

The ESLint half reports 21 errors in 4 categories, all fixed by hand. Formatting lands first so the hand edits are made against already-normalized files and do not have to be re-normalized.

## Affected Code

- `.prettierrc` (new): tabs, single quotes, `trailingComma: none`, `printWidth: 100`, registers `prettier-plugin-svelte` and `prettier-plugin-tailwindcss`, `*.svelte` override to the `svelte` parser.
- `.prettierignore` (new): `pnpm-lock.yaml`, `drizzle/meta/`, `src/lib/server/db/auth.schema.ts`. These are generated by pnpm, `drizzle-kit generate` and `better-auth generate` respectively; reformatting them means the churn returns on the next regeneration.
- 65 files reformatted by `prettier --write .` (68 differing minus the 3 newly ignored): `agent-docs/*.md`, `CLAUDE.md`, `README.md`, `src/**` sources, `svelte.config.js`, `drizzle.config.ts`, `e2e/workspace.e2e.ts`. Whitespace and quoting only, no semantic change.
- `svelte/require-each-key` (7 errors): `CapabilityItem.svelte:13`, `PricingCard.svelte:14`, `BlogPostCard.svelte:42`, `FeatureCard.svelte:26`, `Features.svelte:16`, `RecentPosts.svelte:20`, `RelatedPosts.svelte:14`. Add a key to each `{#each}`.
- `svelte/no-navigation-without-resolve` (10 errors): `RssLink.svelte:5` (`href="/rss.xml"`), `src/routes/+page.svelte:54`, `src/routes/p/[projectId]/+layout.svelte` (7 `goto()` calls). Wrap targets in `resolve()` from `$app/paths`.
- `@typescript-eslint/no-unused-vars` (3 errors): `forgot-password/+page.svelte:16` (`data`), `reset-password/+page.svelte:23` (`result`), `verify-email/+page.svelte:14` (`result`). Each destructures a value it never reads; drop the binding and keep `error: err`.

- `svelte/no-at-html-tags` (1 error): `ChatMessage.svelte:21`. The `{@html}` is already wrapped in `DOMPurify.sanitize(...)` and already carries a comment explaining why the default allow-list is correct. Add a scoped `eslint-disable-next-line` rather than changing behavior.

## Risks

- **65-file reformat is a large diff.** Mitigation: it lands as its own commit containing nothing but formatting, so it can be reviewed with `git show --stat` or skipped with `git blame --ignore-rev`. No hand edits share that commit.
- **Choosing the wrong `.prettierrc` would rewrite the codebase into a style it never used.** Mitigation: the four options were measured before deciding, and the winner is byte-identical to the stock SvelteKit template config; the codebase already uses tabs and single quotes throughout.
- **`require-each-key` on lists of plain strings.** Keying by value breaks if a list ever holds duplicates. Mitigation: for object lists key on the genuinely unique field (`post.slug`, `feature.name`); for the plain-string lists (`CapabilityItem` items, `PricingCard` features, the two `tags` lists) key by index, which preserves today's unkeyed behavior exactly and cannot collide. These are static content lists that are never reordered.
- **Suppressing `no-at-html-tags` could mask a real XSS hole.** Mitigation: the disable is one line, scoped to that call, and the input is already sanitized by DOMPurify. If the sanitize call is ever removed, that is a separate review question, not something this change hides.
- **Reformatting `CLAUDE.md` and `agent-docs/` touches files the docs phase also edits.** Mitigation: formatting commit lands in Wave 1, well before the Phase 5 docs commit.
- **`eslint --fix` is not used anywhere**, so no risk of an automated fixer making a semantic change unreviewed.
